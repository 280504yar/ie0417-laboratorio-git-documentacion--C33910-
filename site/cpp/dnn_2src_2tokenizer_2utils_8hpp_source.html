15// GPT-4’s cl100k_base split pattern
16// NOTE: This pattern is adapted from the original Python regex used for GPT-4's cl100k_base BPE split.
17// The original Python pattern is:
18// r"""'(?i:[sdmt]|ll|ve|re)|[^\r\n\p{L}\p{N}]?+\p{L}++|\p{N}{1,3}+| ?[^\s\p{L}\p{N}]++[\r\n]*+|\s++$|\s*[\r\n]|\s+(?!\S)|\s"""
19//
20// This C++ version differs in the following ways:
21// 1. Possessive quantifiers (`++`, `*+`, `?+`) are replaced with standard quantifiers (`+`, `*`, `?`)
22// because C++ std::regex does not support possessive quantifiers.
23// 2. Inline case-insensitive group `(?i:...)` is replaced with a non-capturing group `(?:...)`
24// because C++ std::regex does not support inline flags. Case-insensitivity must be handled separately.
25// 3. The `$` anchor at the end of `\s++$` is omitted because it's not needed for splitting and may cause issues.
26// 4. Unicode classes (`\p{L}`, `\p{N}`) are kept because the tokenizer's implementation handles them via custom llama.cpp logic.
27//
28// The resulting C++ pattern is compatible with std::regex and the tokenizer's Unicode handling logic.
29static const std::string CL100K_BASE = R"CL100K('(?:[sSdDmMtT]|[lL][lL]|[vV][eE]|[rR][eE])|[^\r\n\p{L}\p{N}]?\p{L}+|\p{N}{1,3}| ?[^\s\p{L}\p{N}]+[\r\n]*|\s*[\r\n]|\s+(?!\S)|\s)CL100K";
